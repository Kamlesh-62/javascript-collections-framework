Add `TreeSet`, a set kept in sorted order and stored as a balanced binary search tree, with the `SortedSet` and `ReadonlySortedSet` types, the `TreeSetOptions`, `SubSetOptions` and `BoundOptions` types and the `isSortedSet` guard. `add`, `has`, `delete` and the nearest-match queries `lower`, `floor`, `ceiling` and `higher` are O(log n); `getFirst`, `getLast`, `pollFirst`, `pollLast`, `removeFirst` and `removeLast` reach the ends. It orders by natural order or by the `comparator` option, and the comparator decides sameness. `subSet`, `headSet` and `tailSet` (with inclusive flags in an options object) return live range views, and `reversed()` a live descending view. Like a native `Set`, `add` returns the set, `has` and `delete` return `false` for `null` and values of another kind in natural order, and `-0` is stored as `0` in natural order. A comparator that throws or returns `NaN` leaves the set unchanged; iteration fails fast; `equals` compares members, so a `TreeSet` equals a `HashSet` with the same members. Building from elements in ascending order takes O(n). `addFirst` and `addLast` throw `UnsupportedOperationError`.
